# Submission Hub v2.0.0 发布审查记录

审查日期：2026-08-02

本记录用于说明 v2.0.0 在合并、部署和创建 GitHub Release 之前执行的三轮发布审查。正式功能说明见 `docs/releases/v2.0.0.md`。

## 第一轮：产品与界面回归

审查范围：Luminous、Luminous X、亮色、暗色、移动端、在线版与离线版。

重点核对：

- 五个一级模块的顺序、语义和选中状态；
- 投稿准备四个二级页面的等宽布局、连续切换与返回总览；
- 期刊中心四类筛选、顶栏与卡片间距、长期刊名和未知指标隐藏；
- 投稿卡片状态入口、稿件后台、出版社操作和期刊悬浮详情；
- 2K 缩放等效视口、超宽屏、窄屏和移动端的列数与溢出；
- 时间线轮次耗时、自定义区间和交互高亮；
- 编辑弹窗、附件预览和页面滚动层级。

结果：现有专项交互、几何和视觉回归继续作为合并必需检查。最近发现的普通视图投稿准备二级导航错位、点击拦截以及期刊中心顶栏紧贴问题已在 v2.0.0 前修复并加入回归约束。

## 第二轮：版本、文档与发布链

发现并修复以下发布级问题：

1. 文档截图工作流固定执行 `npm version 1.5.0`，可能在后续版本中将锁文件回退到旧版本。现改为读取 `package.json` 的当前版本。
2. 离线 Release 工作流固定使用 v1.5.0 标签、标题、说明和文档路径。现改为从 `package.json` 解析版本并读取匹配的更新说明。
3. 截图工作流在分支并发更新时可能因非快进推送失败。现增加完整历史抓取、提交前 fetch 和 rebase，再推送生成结果。
4. 正式 `verify` 原先未覆盖自动期刊档案和私有附件生命周期。两项检查现已纳入发布验证。
5. README、公开发布元数据、版本说明和锁文件新增一致性合同，阻止遗漏版本号、错误日期、旧链接或工作流硬编码进入正式版本。

## 第三轮：最终门禁

合并前要求以下检查全部完成：

- Release metadata consistency；
- Sample privacy；
- Automatic journal catalog；
- Journal selection metadata；
- Journal rank display policy；
- Private document storage lifecycle；
- TypeScript 与在线构建；
- 离线单 HTML 构建与隔离；
- Luminous / Luminous X 页面与首次引导；
- 投稿卡片后台操作；
- UI geometry contract；
- 多分辨率视觉截图；
- 文档截图生成与尺寸校验。

合并后继续核验：

- GitHub Pages 构建、部署与线上 SHA 一致；
- `public/release-info.json` 在线版本为 `v2.0.0`；
- GitHub Release `v2.0.0` 创建成功；
- Release 附件包含通过同一验证链生成的 `submission-hub-offline.html`。

只有上述门禁全部通过，v2.0.0 才视为完成发布。
