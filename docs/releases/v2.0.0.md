# Submission Hub v2.0.0 更新说明

发布日期：2026-08-02

v2.0.0 是 Submission Hub 的第二个主要版本。该版本在不改变既有投稿数据结构和核心工作流的前提下，重新梳理一级信息架构，完成期刊中心、投稿准备、投稿管理、时间线分析、双界面一致性、响应式布局和发布流程的系统性收束。

## 1. 信息架构升级

一级主菜单统一为：

**投稿管理 → 期刊中心 → 投稿准备 → 个人统计 → 后台管理**

- “期刊中心”成为期刊档案、筛选、编辑和投稿入口的唯一一级入口。
- “投稿准备”保留总览、选题池、草稿准备和期刊比较四个二级页面，不再重复显示期刊库入口。
- 点击“投稿准备”始终进入投稿准备总览；点击“期刊中心”直接进入完整期刊档案库。
- 在线版与离线版共享相同的信息架构、页面记忆和业务逻辑。

## 2. Luminous 与 Luminous X

- Luminous 保留顶部导航和高密度横向工作区。
- Luminous X 保留固定左侧栏、状态控制区和集中工具区。
- 两套界面的一级菜单顺序、按钮尺寸、圆角、悬停、选中状态和页面语义统一。
- 期刊中心不再使用区别于同级菜单的独立按钮样式。
- Luminous X 的新增操作统一移动到筛选区域上方，并按当前页面显示“新建投稿”“新增期刊”“新增选题”或“新建草稿”。
- 主题、设置、导入、导出和项目反馈均使用图标加文字；导入与导出保持同一行。
- “项目与反馈”弹窗在视口内向上展开，避免被底部裁切。

## 3. 投稿准备工作区

- 普通 Luminous 的总览、选题池、草稿准备和期刊比较恢复为一行四列等宽导航；窄屏自动切换为 2×2。
- 清除旧版跨列、固定高度和绝对定位规则，避免二级菜单错位、掉行和透明覆盖层拦截点击。
- 在选题池、草稿准备或期刊比较之间切换后，可稳定返回总览。
- 投稿准备总览回归正常文档流，标题栏、二级导航、仪表盘和后续模块依次排列。
- 论文准备助手、选题推进、草稿推进和期刊比较继续使用原有数据与操作逻辑。

## 4. 完整期刊中心

- 期刊中心默认展示全部档案，不再只展示重点收藏。
- 提供“全部、重点期刊、投稿自动收录、手动记录”四类筛选，并显示实际数量。
- 投稿历史中尚未建立档案的期刊可自动生成简易记录，并按规范化期刊名聚合去重。
- 顶部筛选、检索和新增期刊集中在同一信息栏；移除重复菜单行和重复说明栏。
- 顶部信息栏与期刊卡片之间使用独立设计间距，不再发生边框紧贴。
- 期刊卡片保持高密度多列布局，长期刊名、中文名、缩写、出版社、分区、OA/APC、审稿指标和底部链接按内容驱动排列。
- 未知指标、空 APC、空链接和空审稿数据不再保留占位框或空白轨道。
- 超宽屏下卡片按内容高度排列，避免稀疏记录被拉伸出大面积空白。

## 5. 期刊身份、筛选与公开指标

- 中文期刊名位于英文名下方并作为主要辅助身份突出显示。
- 缩写仅显示简洁且学界可识别的形式；冗长 ISO 缩写仍保留在档案和检索数据中。
- EasyScholar 标签支持按期刊独立控制卡片外显，低价值小类默认隐藏。
- 选刊标签、选刊备注、中文简介翻译进入检索、卡片和期刊比较。
- “获取审稿周期”继续从公开来源读取首轮决定、投稿至接收周期和接收率，并保存来源地址。
- Elsevier 与 ScienceDirect 页面可自动派生 Insights 地址，并兼容数值在标签前后的页面结构。
- 公开审稿指标受来源页面结构和统计口径限制，保存前仍需人工核对定义。

## 6. 投稿卡片与后台操作

- 投稿状态成为可操作入口：存在稿件专属后台地址时，可直接从状态或“稿件后台”按钮进入。
- 后台地址优先使用稿件专属 tracking URL，缺失时才回退到期刊通用投稿入口。
- 投稿卡片不再外显低价值的投稿系统名称和稿件编号，但相关字段仍保留用于编辑和检索。
- 出版社标志、出版社名称、稿件后台和投稿入口形成明确操作层级。
- 期刊名称保持卡片头部主要信息，长期刊名缩小字号并限制在两行内。
- 状态、后台原文、出版社操作和题名使用正常网格流，不再依赖固定高度或绝对定位模拟。

## 7. 期刊悬浮详情

- 期刊详情改为锚定在期刊名称下方的悬浮卡片，不再使用覆盖整页的半透明弹层。
- 支持悬停或键盘聚焦临时预览，以及固定、取消固定、关闭、点击外部关闭和 Esc 关闭。
- 悬浮卡片提供“在期刊中心查看”和“编辑期刊信息”。
- 跳转期刊中心后自动定位并突出对应期刊记录。
- 悬浮层尺寸、位置、键盘操作和移动端行为纳入专项回归检查。

## 8. 审稿时间线分析

- 自动识别每轮 Submitted / Revision Submitted 至 Major Revision、Minor Revision、Accept 或 Reject 的反馈耗时。
- 时间线顶部显示首轮返意见、当前轮等待、返修次数、最长阶段和总历时。
- 时间线表格新增轮次分析信息，区分每轮起点、反馈耗时和当前等待时间。
- 支持任选两条时间线事件计算自定义间隔、交换起止节点并高亮对应区间。
- 轮次结果可展开查看该轮内部阶段耗时。

## 9. 响应式布局与空间玻璃界面

- 普通 Luminous 根据有效 CSS 视口调整页面宽度，减少 2K 屏和浏览器缩放下的无效左右空白。
- 投稿卡片列数按有效视口自适应：宽屏保持高密度，多列不足时逐级降为三列、两列和单列。
- 长期刊名、状态、出版社操作和稿件后台在窄卡片内分别约束，不再互相覆盖。
- 两套界面继续使用克制的空间玻璃材质：半透明表面、细边框高光、低强度阴影和轻量背景色场。
- 深色模式优先保证正文、输入框、按钮和卡片边界对比度。
- `prefers-reduced-motion` 下关闭非必要动态效果。

## 10. 附件、账户与数据兼容

- 在线附件继续使用私有 R2 主存储和 Supabase Storage 回退存储。
- 浏览器内预览继续覆盖 PDF、图片、DOCX、XLS/XLSX、CSV、PPTX 和文本文件。
- GitHub OAuth、邮箱密码、邮箱链接、显示名、头像、界面和主题偏好继续共用同一账户数据。
- v3 JSON 备份继续覆盖投稿、期刊、选题和草稿，并兼容旧版备份。
- v2.0.0 不要求新增数据库迁移；已完成 `001` 至 `012` 的部署可直接升级。

## 11. 发布流程修复

本次发布审查发现并修复了两个会影响正式版本的流程问题：

- 文档截图工作流原先固定执行 `npm version 1.5.0`，可能在后续版本中将 `package.json` 和 `package-lock.json` 降回旧版本。现已改为读取当前 `package.json` 并仅同步锁文件。
- 离线 Release 工作流原先固定使用 v1.5.0 标签、标题、说明和文档地址。现已从 `package.json` 动态读取版本，并加载对应的 `docs/releases/vX.Y.Z.md`。

新增发布一致性检查，自动核对：

- `package.json` 与 `package-lock.json` 版本；
- `public/release-info.json` 的版本和日期；
- README 版本徽章、当前版本和更新说明链接；
- 对应版本更新说明文件；
- Release 工作流和截图工作流是否仍包含旧版本硬编码。
