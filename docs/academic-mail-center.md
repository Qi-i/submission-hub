# 邮件聚合 · 在线使用与运维说明

「邮件聚合」是独立于投稿管理的主菜单，不是投稿管理二级页面。Web 使用完整页面宽度，界面采用 Submission Hub 共用的 Luminous/Luminous X 样式，适配移动设备。配置与分类偏好存储在 Supabase，可直接调整，**不需要重新构建前端**。

## 添加与管理邮箱

邮箱与同步 → 添加邮箱 → 配置收发信。支持新疆大学教工/学生、中国地质大学（北京）等 Coremail、QQ、126 以及其他开放 IMAP 的邮箱。Gmail 与 Outlook/Hotmail 的邮箱客户端 OAuth2 仍需独立实现；ChatGPT 连接 Gmail 不会自动同步到本数据库。

IMAP（收信/全部文件夹）：SSL/TLS 993 或 STARTTLS 143。SMTP（发信）：SSL/TLS 465 或 STARTTLS 587。网页登录可分别修改 IMAP/SMTP 主机、端口、加密方式和登录名；服务器必须具有可信 TLS 证书。禁止不加密传输、直连 IP 地址或内部域名。出于防止 SSRF 的要求，服务端在连接前检验域名解析地址，阻断私有/保留 IP。使用自定义域名时，需由用户确认域名属于真实邮件服务商。

「自动发现」尝试服务商预设、邮箱域名候选与 DNS SRV 记录，**返回候选不代表已经通过连接验证**。保存后点击「测试连接」，后端分别检查 IMAP TLS 登录和 SMTP TLS 登录，后者不会发送邮件；只有 IMAP 认证通过的账户才启用云端采集。SMTP 测试不通过不会自动发送任何测试信。现阶段使用同一客户端密码或授权码为 IMAP/SMTP 登录；如两边独立授权码，需使用服务商统一客户端授权码。

既有配置再次修改时授权码可留空，沿用 Vault 中已保存的凭据。不要在 GitHub Issues、聊天、README 或网页 URL 中提交密钥。支持网页撰写和回复**纯文本**邮件，发送前需确认；暂不支持复杂的 HTML 编辑、附件发信、Gmail/Outlook OAuth2。

## 归档、搜索与分析

Supabase Cron 每 10 分钟依次检查已验证的邮箱。采集使用只读 IMAP EXAMINE / BODY.PEEK[]，不会标记已读、删除、移动原邮件；原始 EML 写入私有 Storage `mail-originals`，便于保全服务器定期清空的垃圾邮箱。Web 支持多邮箱全文检索、筛选、阅读原文与手工调整投稿关联。大型 EML （超过 8 MiB）暂不能完整归档，应另行在邮箱提供商原生界面下载保存。容量及配额以 Supabase 实际套餐为准。

在「自定义与 AI」中可新建/重命名/排序/移除快捷视图、紧凑显示、保存用户自己的分类方式。默认的审稿邀请不占固定一级模块，可通过检索或临时快捷入口查看；AI 识别的邮件分类另存为 `ai_category`，不覆盖手工分类。

## 模型 API、测试与自动调用

默认内置 Z.AI `glm-4.7-flash` / `glm-4.5-flash`。已保存的 GLM Key 可在 Web 点击「测试 GLM 连接」；测试会发一个简短的模型提示词，不包含邮箱内容，**可能消耗少量模型额度**。返回有效的 OpenAI 风格 `choices` 才算成功。

自定义模型采用标准 OpenAI Chat Completions 兼容接口（完整 HTTPS `/chat/completions` URL）、模型 ID、昵称及独立加密 Key，可在网站上多账户新增、编辑、删除和逐个测试。不支持未经适配的 Anthropic 或其他非 OpenAI 风格私有协议。删除自定义接口时，服务端删除 Vault 密钥。服务端限制为有效公网 HTTPS、443 端口、可信证书及不跟随跳转，禁止访问内网、IP 或元数据接口。

系统指令可在网页编辑和保存，用户写的分析要求只在固定安全约束之下生效。AI 返回 summary、tags、priority、action、category 后写入邮件索引，原始邮件和已手动编辑的分类保持不变。自动分析**默认关闭**，仅在用户配置凭据、选择模型且主动开启时执行；默认只处理开启后收到的新邮件。每天最多 50 次（用户可以设 0、5、10、20、30、50），后台每轮至多四封邮件。启用「分析历史邮件」后才会回填既有数据。

默认 Flash 不会回退到收费模型；自定义模型若未标明免费则必须在模型级和用户设置中进行两次明确的费用许可。服务商“免费”的实际额度、收费策略会变化；免费声明不构成零费用保证。未经单位允许，不应将敏感学校邮件内容发送给第三方模型服务商。

## 权限与运行

- 邮箱密码、AI Key 存于 Supabase Vault；只能由授权的服务端 Edge Function 访问，不能在 GitHub 仓库、浏览器或公开数据库直接读取。
- 账户、邮件索引、模型信息采用逐用户 Supabase RLS；邮件原文保存在私有 Storage。
- 所有关键 Edge Function 要求用户 JWT 或仅限后台 cron 内部密钥。Cron 查询只在存在可处理邮箱/邮件时调用函数，尽量减少空转。
- AI 输出只作为不可信建议，不执行邮件指令、不自动发送邮件或修改稿件状态。
- Gmail/Outlook OAuth2 尚未接通；真实 IMAP/SMTP 登录、收发与 GLM 模型测试须在用户自己的网页登录态和授权下执行，不能由仓库静态构建代替。

## 配套实现

数据库迁移 `012` 至 `024`；云端 Edge Functions 包括 `mail-config`、`mail-cloud-collector`、`mail-send`、`mail-ai-settings`、`mail-ai-analyze`；React 页面 `AcademicMailCenter` 和 `MailPersonalization`。检查命令 `npm run verify`，新增架构审查已并入现有 `npm run check:mail-center`（独立运行：`node tests/mail-first-principles-contract.mjs`）。

当前在线版保持 `v2.1.0`，此后对邮件模块的修复不会自动创建 GitHub Release 或额外安装包。


## 同步稳定性与独立 SMTP 授权（增量维护）

- 添加或修改邮箱后，网页自动先保存配置，再进行 IMAP/SMTP TLS 登录测试。只有通过 IMAP 验证，才标记可自动收信；单独的 SMTP 登录失败不影响收信，但界面会明确显示失败原因。
- SMTP 可选择与 IMAP 共用授权码，或填写自己的独立 SMTP 客户端密码；两者加密隔离保存在 Supabase Vault，输入框不会显示原始值。重新使用共用授权码时，独立 SMTP 密钥将从 Vault 删除。
- 邮箱卡片提供「暂停采集 / 恢复采集」。恢复操作必须重新验证 IMAP 登录。每次自动扫描记录上次成功时间、处理封数和扫描文件夹数，异常显示具体原因及下次自动重试时间。
- 自动采集故障采取指数退避（30 分钟、2 小时、6 小时、12 小时、24 小时），防止失效授权码每十分钟反复撞库。手动检查允许提前诊断，成功后清零失败计数。
- 修复了手动采集时后端返回 HTTP 200 携带错误，前端却误提示成功的问题。当前界面会直接呈现采集失败详情。
- 自定义 AI API 地址、模型 ID 或费用属性发生变化时，数据库触发器会撤销旧接口授权标记并关闭自动分析，必须保存对应 Key 并再次主动启用，以防旧 Key 意外发送到新目的地。
- 保持 v2.1.0 不变；仅更新 GitHub Pages 在线版本，不创建新 Release 或离线资源。

## 邮箱地址校验、GLM 平台与页面悬浮提示（2026-10-22）

针对已正常使用的邮箱域名遭到误拒绝的问题，**保存邮件服务器参数仅校验公网域名格式和安全端口**，不再把 Edge Runtime 的 `Deno.resolveDns` 查询结果强行视为邮箱真实有效性的判据。实际可用性由服务端发起 IMAP/SMTP SSL/TLS 或 STARTTLS 握手和登录决定；有问题会显示在各协议连接测试详情，而不是在保存阶段报“域名无法解析”。服务器必须具备可信证书，并禁止内网域名、IP 直连、不安全端口和无加密协议。

GLM-4.7-Flash 免费模型可选择 `https://open.bigmodel.cn/api/paas/v4/chat/completions`（国内智谱 BigModel）或 `https://api.z.ai/api/paas/v4/chat/completions`（国际 Z.AI）。由于两个平台的 API Key 可能不互通，Web 提供“自动检测官方平台”**明确授权操作**：用户点击后，最多向这两个官方端点发送最短、无邮件正文的探针，找到可用平台后保存选择，但不自动开启分析。错误反馈拆分为 1113（额度/平台）、1302（请求频率）、1305（服务繁忙）以及独立的鉴权/模型参数/网络错误；不再把所有 429 归类为限流。运行时遇到暂时性 429，会让原邮件继续保持待分析，并延长下一次尝试时间，而不会把邮件永久标记为失败。

邮件列表、邮箱设置与 AI 设置统一通过 React Portal 把提示挂载到 `document.body`，使用固定视口定位；成功提示及一般警告定时消失，严重错误需要手动关闭。页面纵向滚动和组件自身的窄容器不再影响用户查看反馈。

**本轮仅更新在线 Web 与 Supabase Functions，保持 v2.1.0 不变，不生成新的 Release、安装包或离线资源。**


## 2026-10-22 多模型路由与免费慢速容忍

- **内置多模型**：GLM-4.7-Flash、GLM-4.5-Flash 各有独立测速结果，同一已保存的 Z.AI 或 BigModel Key 在同平台内复用；已有自定义模型和其专用 Vault Key 也可加入路由序列。页面支持勾选/移除、最多六个节点及上移/下移。所有排序即时保存到本人 Supabase 首选项，不需要上线新代码。默认保持单模型调用，**自动路由关闭**。
- **失败自动接力**：明确打开自动接力后，以页面显示的路由次序尝试当前可用节点。每个 API 请求前都重新核对用户身份范围、已保存的有效 Key、供应商/URL 的加密与公网约束。内置两个 Flash 模型可以接力；自定义备用模型必须已经通过真实 API 测试且由用户声明免费。**即使用户允许了某个收费模型，也不会将它加入自动接力**。关闭接力时仍保留人工选择单个可能收费模型的双重显式授权逻辑。
- **慢速容忍**：可点击各模型「测速度」并保存实际响应耗时，非瞬时 429 才算测速成功；网页显示速度。允许 30、45、65 或 90 秒单请求上限。慢速模式默认开启，工作线程按测试时间（约 3×历史响应时间再增加裕量）、最高 60 秒的基础容忍窗口和用户上限自适应；关闭后采用偏快的 25 秒上限。测试本身使用完整的用户等待上限，而不是原来固定的 16 秒。
- **有限云端任务预算**：Supabase 免费计划的单次 Edge Function 墙钟限制约 150 秒；后台任务内部设约 115 秒预算，另留网络、数据库开销。一次模型尝试即消耗一次 `mail_claim_ai_slot` 日额度；有待处理的慢速邮件可以交由下次 10 分钟任务处理，不能承诺单轮处理全部。临时失败 / 限流 / 超时保持消息的 `pending` 状态并设置冷却窗口；全部授权或余额错误时自动停止 AI 并提示需要人工处理。
- **数据保密**：自动接力可能将同一封邮件的内容片段交给两家不同第三方模型商，必须主动选择；未添加并测试的接口不会自动发出请求。没有付费回退，不以关闭 TLS 安全校验作为提高兼容性的手段。

## Outlook OAuth2 与玻璃工作台（2026-10-22）

### Outlook / Hotmail 已增加 Microsoft Graph OAuth2 接入

邮件聚合 → 邮箱与同步 → Outlook 账号卡片 → 「连接 Microsoft 账户」。网页填写微软 Entra 应用注册的 **Application (client) ID**（公开标识，不是密码），点击「开始 Microsoft 授权」。页面显示设备授权码，点击「打开微软授权页」登录对应邮箱、输入验证码并同意权限；网页按 Microsoft 返回的轮询间隔自动检测，授权成功后自动进行一次 Graph 邮件归档。

**需要一次性的微软应用注册**：在 [Microsoft Entra 应用注册](https://entra.microsoft.com/#view/Microsoft_AAD_RegisteredApps/ApplicationsListBlade) 创建应用，支持「任何组织目录中的账户和个人 Microsoft 账户」；在「身份验证」→ 高级设置打开 **Allow public client flows**。配置 Microsoft Graph 委托权限 `User.Read`、`Mail.Read`、`Mail.Send`，授予 `offline_access`。设备代码流无需 Web 重定向地址、客户端密钥或个人邮箱密码。部分公司/学校租户禁止公共客户端应用或要求管理员同意，届时必须按微软租户政策办理，不能通过改 SMTP 服务器绕开。

OAuth2 设备授权码放在私有数据库并由 Vault 加密，15 分钟左右过期；Access Token 不存浏览器。Refresh Token 通过 Vault 加密，云端定时刷新；断开连接会清除本系统保存的令牌，已有邮件归档保留。如需取消 Microsoft 授权，须到微软账户的应用访问权限管理页面撤销。

授权后使用 Microsoft Graph `/me/mailFolders?includeHiddenFolders=true` 递归枚举子文件夹、垃圾箱及隐藏文件夹；使用 `/me/messages/{id}/$value` 保存原始 MIME / EML 到私有 Storage。增量获取最近邮件，并通过每文件夹 Graph continuation URL 持续历史回填（单次服务有时间、大小和条数限制）。无需常开电脑。Outlook 发信使用用户授权的 `Mail.Send` 访问 `/me/sendMail`，不要求 SMTP 主机或应用密码，只有用户确认「发送」后才提交。

**限制**：未填入有效 Microsoft 应用客户端 ID 或尚未在微软网页登录授权前，Outlook 仍显示未连接；不能宣称账户已同步。Microsoft Graph 可能限制速率，单封超过 8 MiB 的 EML 无法归档，刷新令牌被撤销后需重新授权。设备授权中不收集微软账户密码；如邮件地址与所登录账户的主地址不一致，会主动拒绝绑定，避免错误归档他人邮箱。特殊 Outlook 别名账户可能需要以实际邮箱地址重新添加。

### UI 全站一致性审查与落地

邮件中心全面改为与 Submission Hub 的现有 Luminous token 兼容的多彩玻璃系统：页面顶部渐变 Hero，分离邮箱接入、归档数量、AI 运行状态；三个工作区使用同一分段导航；不同邮箱服务商有对应的彩色边缘提示。邮箱摘要默认为双列卡片，展开连接或 OAuth2 授权后自动占满整个内容宽度；邮件列表与阅读区维持双栏。模型设置按功能模块双列布局，蓝青（快捷视图）、紫色（服务商）、绿色（路由）、橙色（自动分析）区分，不再排列为漫长的单列表单。悬浮通知采用统一玻璃语义颜色，支持暗色主题和低动态效果。移动端自适应堆叠，输入框与主控按钮沿用站点字体和交互间距。

## 跨邮箱整理、备注、来源标识与翻译（2026-10-22）

邮件聚合新增跨邮箱虚拟文件夹（例如投稿进展、审稿、学术交流）、多标签及私人备注。与服务器原生文件夹不同，虚拟文件夹仅是 Submission Hub 的组织字段，不会移动 IMAP、Graph 中的原件，也不会改变原始 EML 或云端归档位置；不同邮箱的邮件可以纳入同一个虚拟文件夹。标签可从统一词表多选，跨邮箱筛选；删除标签会清除邮件上的相应标签，但保留邮件。文件夹、标签、译文均实施当前用户 RLS 隔离。

邮箱与同步页提供来源简称、自定义文字图标及 HTTPS Logo URL，可将学生、教职工、CUGB 等邮箱分别标为易辨认的名称。列表显示图标与简称，详情同时保留完整地址及真实服务端文件夹名称。自定义 Logo URL 是用户输入的远程地址，建议使用可信来源；没有 URL 时显示自定义字符或内置服务商符号，不自动加载发件人邮件中的任意图片。

邮件正文右上角「翻译对照」展示原文与简体中文 / English 译文，并提供按需翻译。使用已加密配置的免费 GLM Flash 或已测试、已声明免费的自定义模型；故障路由仅在用户启用时尝试下一免费模型。绝不自动调用收费模型；每次真实请求计入每日 AI 次数。每次翻译只传送源正文前 8500 字，余下原文仍可阅读。译文独立存储且含源文本 SHA-256 指纹，重复访问优先命中缓存，便于区分机器译文和真实邮件。

版本保持 v2.1.0，仅更新 GitHub Pages、Supabase migration / Edge Function，无新增 Release 或安装包。
